# Quasar Bridge

Go-сервер для выборочной обработки запросов Яндекс Станции через нативный
WebSocket-протокол Quasar/Uniproxy.

- Умный дом обрабатывает Home Assistant через MCP.
- Сложные вопросы и распознанные текстовые отказы Алисы обрабатывает
  OpenAI-совместимая LLM.
- Остальные запросы передаются в Яндекс.

Распознавание речи и синтез остаются в Яндексе. Это не автономная работа без
интернета. Протоколы: AAPI protobuf для управляющих сообщений и отдельные
аудиокадры. Схемы: [freequasar/quasar-go-genproto](https://github.com/freequasar/quasar-go-genproto).

## Настройка

Требуется Go 1.27.3+. Сборка не требует CGO.

```sh
cp config.example.json config.json
cp runtime.env.example runtime.env
chmod 600 config.json runtime.env
```

Замените адреса-примеры и `your-model` своими значениями. Реальные файлы
`config.json`, `runtime.env`, сертификаты, ключи и журналы исключены из Git.
Секретный URL Home Assistant MCP хранится в `QUASAR_HOME_MCP_URL`, ключ API
LLM — в необязательном `QUASAR_LLM_API_KEY`.

| JSON | Переменная окружения | Назначение |
| --- | --- | --- |
| `listen` | `QUASAR_LISTEN` | Адрес и порт HTTP/TLS-сервера |
| `upstream` | `QUASAR_UPSTREAM` | Штатный WebSocket upstream |
| `mode` | `QUASAR_MODE` | `observe` или `hybrid` |
| `tls_cert` | `QUASAR_TLS_CERT` | Путь к сертификату сервера |
| `tls_key` | `QUASAR_TLS_KEY` | Путь к приватному ключу |
| `allowed_ips` | `QUASAR_ALLOWED_IPS` | IP клиентов; в окружении через запятую |
| `llm_base_url` | `QUASAR_LLM_BASE_URL` | OpenAI-совместимый базовый URL с `/v1` |
| `llm_model` | `QUASAR_LLM_MODEL` | Идентификатор модели |
| `home_warm_area` | `QUASAR_HOME_WARM_AREA` | Необязательная область подготовки кеша HA |

Переменные окружения имеют приоритет над JSON. По умолчанию используется
`localhost:8443` и режим `observe`. Пустой `allowed_ips` отключает фильтр IP:
при открытии доступа из сети задайте адрес прослушивания и явный список клиентов
в своём приватном файле настроек. `hybrid` требует LLM URL/модель и HA MCP URL.
В URL не допускается встроенная пара логин/пароль; ключ LLM передаётся отдельно.

### TLS

Скрипт принимает настраиваемый SAN, без зашитых адресов:

```sh
sh scripts/create-cert.sh certs DNS:localhost
```

Для колонки укажите DNS-имя или IP именно вашего сервера (`DNS:...` или `IP:...`).
Сертификат сервера действителен 90 дней, CA — 365 дней. Существующие файлы
скрипт не перезаписывает. Приватные ключи остаются на сервере; на колонку
переносится только публичный CA.

### Запуск

```sh
set -a
. ./runtime.env
set +a
go build -trimpath -o bin/quasar-bridge ./cmd/quasar-bridge
./bin/quasar-bridge -config config.json
```

Для прозрачной передачи используйте `config.observe.example.json` как основу.
`GET /healthz` показывает режим и счётчики кадров; WebSocket — `/uni.ws`.
Административного HTTP API управления домом нет.

```sh
./bin/quasar-bridge -config config.json -check-backends
./bin/quasar-bridge -config config.json -query 'Горит ли свет в кабинете?'
```

`-query` использует тот же маршрутизатор и обработчики. Команды в нём могут
реально управлять устройствами.

## Home Assistant

Обнаруживаются сущности, разрешённые для Assist (`conversation=true`).
Состояния берутся из текущего `ha_search`, состав групп — из
`member_entity_ids`. Настройки Adaptive Lighting не считаются освещением при
ответах о состоянии. Разрешения обнаружения кешируются на две минуты;
перед действием они проверяются снова. `home_warm_area` заранее подготавливает
и периодически обновляет кеш света/выключателей выбранной области без действий.

LLM выбирает цели из обнаруженных сущностей и ограниченного списка сервисов.
Перед исполнением проверяется весь план: неизвестные и недоступные цели,
неразрешённые поля, повторные цели и пересечение группы с участниками
отклоняются. Максимум четыре действия. Вопросы о состоянии отделены от
планировщика действий. Более 80 кандидатов или контекст свыше 24 КБ требуют
уточнения; предел обнаружения — 2000 сущностей на домен.

После сервиса читается `ha_get_state`. Для включения/выключения `light`,
`switch`, `fan` проверяется итоговое состояние; прочие команды подтверждаются
только как отправленные. Ошибка HA не вызывает повторного исполнения в Яндексе.
Поддерживаемые сервисы перечислены в `internal/home/controller.go`.

Выбор целей моделью вероятностный: команда для всей комнаты может пропустить
отдельный светильник. Проверяется состояние выбранных целей, а не гарантированное
покрытие всей комнаты. После общей команды полезна проверка состояния; при
необходимости назовите отдельный светильник явно.

## Подключение колонки и откат

Нужен уже полученный root и резервная копия конфигурации колонки.
Настройте `aliced.uniProxyUrl` на URL вашего сервера и отключите обход через
`uniProxyQuicUrl`, если он используется. Добавьте публичный CA сервера в доверие
колонки. Прошивки различаются; смотрите `scripts/apply-pilot.sh` до применения.
Скрипт получает приватный подготовленный файл `quasar.cfg.pilot` и публичный CA
в каталоге staging; он не содержит адреса сервера или данных конкретного устройства.
Исходный `quasar.cfg` может содержать данные аккаунта — не добавляйте его в Git.

Пути firmware и резервных копий можно переопределить одинаковыми переменными
для применения и отката: `QUASAR_DEVICE_CONFIG`, `QUASAR_DEVICE_CA_BUNDLE`,
`QUASAR_DEVICE_BACKUP_DIR`. Значения по умолчанию соответствуют типовой firmware.

`rollback-pilot.sh` восстанавливает исходную конфигурацию и CA; после этого
нужна перезагрузка колонки. Сначала восстановите штатное подключение колонки,
затем останавливайте прокси. Для быстрого отключения локальных обработчиков
можно переключить сервер в `observe`.

## Linux/systemd

`scripts/quasar-bridge.service` — пример с отдельным пользователем
`quasar-bridge`, программой в `/opt/quasar-bridge` и настройками в
`/etc/quasar-bridge`. Создайте служебного пользователя, установите бинарник,
настройки и сертификаты с нужными правами; пути и пользователя можно менять
в unit-файле или systemd override. Относительные TLS-пути считаются от
`WorkingDirectory`; для установки удобны абсолютные пути в приватном config.

При фактическом пересечении сети контейнеров и адреса LLM может понадобиться
точечный маршрут. Необязательный шаблон `quasar-host-route.service.example`
берёт назначение, шлюз и интерфейс из приватного `route.env`;
пример переменных — `scripts/route.env.example`. Основной сервис не включает
такой маршрут автоматически.

## Проверки и публикация

```sh
go test -race ./... -count=1 -timeout=60s
go vet ./...
python3 scripts/check-public-tree.py
gitleaks git --redact
```

Проверка Python сканирует Git index, не печатая обнаруженные значения.
Она отслеживает шаблоны секретов и идентификаторов установки, включая приватные
сетевые адреса. Это дополнение к Gitleaks и просмотру коммита, а не гарантия
обнаружения любого секрета. CI запускает проверки дерева, Go-тесты, vet и сборку.

Бинарники, архивы стенда и отчёты с реальными адресами не публикуются.
Сборка `-trimpath` не записывает локальные пути разработчика в бинарник.
Результаты и ограничения проверок: [docs/validation.md](docs/validation.md).
